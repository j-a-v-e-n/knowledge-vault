# 本项目的 AI 工作规则

本文件只保存跨模型、跨候选仍稳定的规则。具体当前状态只看 STATE.json，具体当前步骤只看它指向的 active ExecPlan。

## 每次启动

1. 在本目录运行 python3 -B verify_control_plane.py。
2. 按 README.md 的顺序读完控制面。
3. 用自己的话 dump：最终目标、当前阶段、exact candidate、已知 blocker、权限、下一安全动作、当前决策节点及回溯目标。
4. 校验失败或文件冲突时，进入 STALE_STATE；不得继续候选、freeze、Shadow 或外部动作。

## 每次只推进一个可验证单元

- 启动一个新项目或新的重大阶段前，先完成“问题定义 → 独立第一性推导 → 一手资料与反例调研 → 对照修正 → 最小可证伪方案”。调研必须声明来源宇宙、停止规则、覆盖缺口，并把外部证据、我们的推导和待验证假设分开。
- 外部经验用于挑战、补充和触类旁通，不能因来源权威而自动成为本项目决策；每项采用都要说明适用条件和反证。
- 先写清这一步减少哪个未知或阻止哪个具体失败。
- 写清输入、输出、预算、停止条件、行为验收和失败分支。
- 执行后立即验证；不能把“创建了文件”“测试跑绿”“模型说完成”单独当作结果。
- 更新 active ExecPlan 和 STATE.json 后才进入下一步。
- 同一文件同一时刻只能有一个写入所有者；并行代理优先做互不依赖的只读研究、反证或测试。

## 卡住时必须沿决策链回溯

无进展不是默认要求模型继续努力。满足 RUNBOOK.md 的 stall 证据时：

1. 停止同类重试并保存失败事实。
2. 区分执行错误、工具接口错误、计划错误、关键假设错误或问题定义错误。
3. 在 DECISIONS.jsonl 找最近一个仍有未试替代的分叉。
4. 重验该节点的 basis 和 falsifiers，选择副作用更小、能更快反证的替代支路。
5. 替代支路仍失败时继续向父节点回溯；不得删除失败历史来制造成功。

## 不可变边界

- 最终目标是解决真实需求并形成自愿交易，不是完成治理文档。
- 第一性原理推理与现实观察分别记录；原始观察不得被理论改写。两条 lane 只能在形成假设时合并。
- 事实、解释、假设、实验结果和商业结论必须分开。
- 模型、提示词、聊天摘要和 memory 不能成为项目唯一事实载体。
- 更换模型不得改变目标、权限或验收标准；必须通过 MODEL_ADAPTER_CONTRACT.md 的接管测试。接管资格是兼容性结论，不是授权来源。
- 当前禁止真人联系、公开发布、账号操作、部署、支付、收款、合同和交付承诺。只有用户新的明确授权与实际运行环境能力才能改变这组权限；修改 STATE、verifier 或 review receipt 都不能扩权。
- C7/C8 历史字节、FAIL 记录和 legacy quarantine 不得被重写成 PASS。
- 机械测试、同源模型自评和多数代理投票都不能单独签发高影响权限。

## 何时停止设计并进入现实

C8 只需闭合“最小只读 Shadow 所必需、且能阻止已复现错误或越权”的 Critical/Major 风险。Fresh review 达到预先声明的通过条件后，不得仅因“还能更严”继续新增 Gate。此后必须进入最小 synthetic/read-only Shadow；Shadow 后必须回到现实锚点，或明确简化/停止。
