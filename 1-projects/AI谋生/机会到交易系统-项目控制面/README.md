# 机会到交易系统：项目控制面

这里是整个“机会到交易”长期项目的稳定控制面。它跨 C8、未来候选和模型切换持续存在；它不属于任何候选 inventory，也不能替任何候选签发 PASS、freeze 或外部行动权限。

## 一句话北极星

发现真实需求，验证谁愿意为什么结果付出代价，用 AI 高效做出并交付解决方案，形成自愿交易，并把结果反馈到下一轮。

文档、代码、测试、manifest 和审查只有在减少关键未知、降低真实风险或使下一次现实实验更便宜时才算项目进展。它们本身不是商业进展。

## 开始或恢复任务

无论使用 Codex、Claude 还是其他模型，都从本目录启动，并按以下顺序恢复：

1. 运行 python3 -B verify_control_plane.py，避免在控制面生成 bytecode。
2. 读 STATE.json，确认当前状态、exact candidate、权限、下一安全动作和回溯点。
3. 读 PROJECT_CHARTER.md，恢复最终目标、范围、成功标准和现实进展标准。
4. 读 exec-plans/active/ 下 STATE.json 指定的唯一当前计划。
5. 读 DECISIONS.jsonl，理解当前路线为什么被选择、什么证据会推翻它。
6. 读 RUNBOOK.md；模型接管或更换时再读 MODEL_ADAPTER_CONTRACT.md。
7. 开始行动前先用一段简短状态 dump 说明“已有、做到哪、什么能用、这次要达成什么”。

任何关键文件互相矛盾时，状态是 STALE_STATE：停止写候选、停止宣称完成，先修复控制面的一致性。

## 四层 Harness

1. 项目执行 Harness：本目录。负责长期目标、状态、计划、回溯、权限、模型接管和退出设计阶段。
2. 机会领域 Harness：C8 及其后继。负责把现实观察转成可证伪的需求假设，并阻止语义自称和越权。
3. Eval Harness：领域测试、恢复盲测、反例和整体审查。它验证结果，不替代现实需求证据。
4. 单个机会的交付 Harness：只有需求达到相应证据等级后才生成，负责具体产品的构建、验收和交付。

模型是可替换执行器，不是第五个事实库。模型自己的聊天记忆、总结或“我认为完成了”都不是权威状态。当前只完成 provider-neutral 合同设计，尚未由另一种 provider/runtime 验证可移植性。

## 当前事实

- 当前 C8 仍是 PRE-FREEZE-REVIEW-ATTEMPT-1-FAIL。
- C8 的 canonical FINAL_CANDIDATE_MANIFEST.json 仍标识 C7，是历史冻结对象，不是 C8 的 living state。
- 当前没有 C8 governance、shadow 或 shadow-review root。
- 当前没有真实商机、购买意愿、交付或交易证据。
- 当前外部行动权限为 false；不得联系真人、发布、部署、支付、收款、签约或作出交付承诺。
- STATE 中的 authority 只描述用户与运行环境已经给出的范围；workflow_gates 只决定现在是否该做，二者都不能由文件本身扩大真实权限。

最新的精确状态只看 STATE.json。

## 控制面文件为何存在

| 文件 | 防止的失败 | 如何验证 | 何时可删除或合并 |
|---|---|---|---|
| PROJECT_CHARTER.md | 局部优化吞掉最终目标 | 恢复盲测能说出北极星和现实成功标准 | 只有上位 charter 完整承接且盲测通过 |
| STATE.json | 重启后靠聊天猜当前状态 | 机械校验路径、hash、权限和计划引用 | 不可删除；可迁移到等价机器状态库 |
| exec-plans/active/ | 一次规划后长期漂移 | 每步有行为验收、恢复点和完成后状态 | 当前计划完成后移入 completed |
| DECISIONS.jsonl | 卡住后只在末端无限修补 | 能定位最近分叉、反证和回溯目标 | 只有等价决策图承接全部历史 |
| RUNBOOK.md | 每个模型采用不同执行循环 | 恢复与交接演练得到同一下一步 | 只有自动执行器完整实现并通过回归 |
| MODEL_ADAPTER_CONTRACT.md | Harness 被某个模型或聊天锁定 | 新模型通过同一接管测试 | 仅当接口成为平台级强制合同 |
| research/ | 把流行说法当成已证事实 | 主张可追到一手来源并保留限制 | 证据被更新研究完整承接 |
| evals/ | 文件齐全被误当成可用 | 独立代理仅凭文件恢复并接受挑战 | 等价自动化与独立评测完整承接 |

新增任何长期文件或 Gate，都必须在这张表或 RUNBOOK 的 Complexity Gate 中说明它阻止什么已观察失败、最简单替代是什么、如何验证、何时退休。
