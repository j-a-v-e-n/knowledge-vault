# 商机发现系统：双通道设计 v0.1

> 日期：2026-07-27  
> 状态：设计候选；只读影子验证前，不修改正在运行的创新闭环，不触发外部联系、发布、开发或收款  
> 来源：Javen 本轮第一性原理讨论 + 现有 `创新闭环` 运行证据 + 既有机会发现研究档案

## 0. 当前状态 dump

### 已经有什么

- `创新闭环` 已经能够读取公开网络信号、生成候选、执行内部 gate、维护击杀清单和日报。
- 2026-07-27 监事会记录：近 28 天读取信号 1033 条，生成候选 106 个，gate 放行 66 个。
- 同一记录显示：商业探针 2 个均为 `not-run`，funnel 均为 `null`；截至该报告，准备的帖子没有实际发出，系统没有获得真实市场接触结果。
- 既有研究已经定义 Observation、Interpretation、Hypothesis、ExperimentResult 分离，以及 E0–E5 需求证据阶梯，但这些原则尚未成为当前创新闭环的主执行结构。

### 做到哪里

系统已经证明自己能持续完成“采集 → 生成 → 内部裁决”，但尚未证明它能完成：

`发现真实需求 → 获得外部承诺 → 产生使用 → 发生付款 → 形成留存`。

因此，信号数、候选数、gate 通过数是过程证据，不是商机发现成功的证据。

### 什么能用

- 已有采集器和冻结语料：可继续作为现实观察来源。
- 原始来源回链、冻结存档、失败记录：可复用。
- 权限 gate 和商业探针结构：可复用，但需要重新定义晋级条件。
- 现有 GENERATE、内部竞争和一夜代码尺子：可作为“创意/可构建性实验”，不能继续被解释为需求验证。

### 这次想达成什么

建立一套新的商机发现认识与执行结构：

1. 第一性原理推导与网络现实观察先独立运行；
2. 不允许两者在采集阶段互相污染；
3. 只有在受控综合阶段才连接；
4. AI 只能生成需求假设，不能用自己的判断证明需求；
5. 商机状态只能被外部行为证据推进；
6. 最终目标是交易与可持续价值，不是内部候选吞吐量。

## 1. 第一性原理定义

### 1.1 商业的最小结构

一个主体处于状态 A，希望进入更理想的状态 B；中间存在阻碍、成本、风险或能力缺口；另一个主体帮助其完成转变；双方认为交换后的净结果优于不交换。

```text
当前状态 A
    ↓  存在不满意、风险、欲望或任务
目标状态 B
    ↓  自己完成有阻碍
解决者提供状态转变
    ↓  价值、信任、权限和代价均可接受
发生交换
```

### 1.2 需求不等于商机

商机至少是以下条件的交集：

```text
特定人群
∩ 特定情境中的状态差距
∩ 足够重要的阻碍或成本
∩ 不满意的现有替代方案
∩ 可触达的使用者或付款者
∩ 愿意且有能力交换
∩ 我们能够合法、可信、经济地交付
```

缺少任何一项，都只能保留为待调查假设。

### 1.3 稳定层与变化层

相对稳定的不是某个产品类别，而是：人会偏好某些状态、回避某些状态、在约束下行动，并在预期收益足够时交换资源。

快速变化的是：

- 满足欲望的技术；
- 人们所在的渠道；
- 可接受的价格和速度；
- 法律、平台、信任与竞争环境；
- 谁是使用者、影响者和付款者。

系统不能用流行产品名替代底层需求，也不能用抽象“人性”跳过具体交易条件。

## 2. 为什么旧闭环会产生“高活动、低真值”

### 2.1 输入在生成前已经混合

现有北极星把“领袖判断、跨领域概念、社区痛点”设为同等地位的一等信号，并共同为 GENERATE 提供方向。

这里混合了三种本质不同的对象：

- 领袖判断：对未来技术或产业的观点；
- 跨领域概念：潜在解决能力；
- 社区痛点：关于现实处境的观察线索。

当它们在生成前混合，AI 很容易用一个流行技术解释所有抱怨，再把这种解释包装成“用户需求”。

### 2.2 内部裁决替代了外部真值

候选由模型生成，再由模型、代码形式检查和内部竞争裁决。即使生成与裁决使用不同 checkpoint，它们仍然面对同一套内部叙述，而不是客户行为。

内部 gate 能回答：

- 叙述是否完整；
- 引用是否存在；
- 是否有可运行的一夜实验；
- 相比其他候选是否更符合内部标准。

它不能回答：

- 问题是否重要；
- 对方是否愿意改变现有行为；
- 谁会付款；
- 是否会重复使用；
- 获客成本是否低于可获取价值。

### 2.3 “一夜代码可证伪”选择了错误的优化对象

一夜代码尺子适合验证可构建性、技术机制和局部性能，但真实需求往往需要观察、承诺、使用和交易才能证伪。

把一夜代码判定设为所有机会的晋升前提，会系统性偏向：

- 容易写成工具的问题；
- 开发者自己熟悉的问题；
- 能被内部 benchmark 表达的问题；

并排斥：

- 信任密集型服务；
- 分发、定价和交易机制；
- 需要真实情境才能暴露的问题；
- 暂时可由人工交付、尚不需要软件的问题。

### 2.4 闭环终点定义错了

现有北极星写明“闭环的终点在 AI 这一侧”。这适合做 AI 自我改进实验，却与本项目的商业目标冲突。

商机闭环的终点必须在现实世界一侧：

```text
某个人的状态真实改善
＋
对方完成真实交换
＋
我们能够持续交付
```

AI 的学习回流是支持层，不是商业闭环终点。

## 3. 新架构：两条独立通道 + 一个受控桥梁

```text
通道 A：第一性原理模型                 通道 B：现实观察账本
不读每日网络语料                        不读取理论标签
推导人、状态、阻碍与交换条件            忠实记录谁在何种情境做了什么
输出 PrincipleModel                    输出 ObservationCard
               \                       /
                \                     /
                 └── 受控综合桥梁 ───┘
                         ↓
                   NeedHypothesis
                         ↓
                   现实验证阶梯
                         ↓
             承诺 → 使用 → 付款 → 留存
```

### 3.1 通道 A：第一性原理模型

#### 输入

- 对商业交换的基础定义；
- 相对稳定的人类动机候选；
- 约束、信任、权限、风险与交易条件；
- 已经通过真实外部结果验证的反例。

#### 禁止输入

- 当日热搜、产品发布、领袖预测；
- 某一批待分析帖子；
- 当前候选产品名称；
- 候选的内部评分和排名。

#### 输出

版本化的 `PrincipleModel`：

- 状态 A / 状态 B；
- 可能的基本驱动力；
- 阻碍类型；
- 交换成立的必要条件；
- 会推翻或修正该模型的现实反例。

#### 更新规则

不因日常网络信号自动更新。只有经过单独复核的真实行为、付款、留存或明确反例，才能提出版本变更；变更必须保留旧版本和理由。

### 3.2 通道 B：现实观察账本

#### 输入

- 原始帖子、评论、评价、求助、工作描述；
- 人们正在使用的 workaround；
- 可核验的时间、金钱、错误、等待和放弃行为；
- 现有产品、服务和购买行为。

#### 允许做

- 去重；
- 提取原话和情境；
- 标识角色、任务、动作、后果和替代方案；
- 记录缺失信息；
- 将明显转载归为同一来源族。

#### 禁止做

- 宣布“真实需求”；
- 推断“用户一定愿意付费”；
- 提议产品；
- 用第一性原理标签改写原话；
- 根据情绪强烈程度直接计算商机分数。

#### 输出：`ObservationCard`

```text
observation_id
source_uri / captured_at / independence_group
actor（谁）
context（在什么情境）
task_or_goal（正在试图完成什么）
observable_action（实际做了什么）
friction_or_consequence（观察到的阻碍或结果）
current_workaround（当前替代方案）
resource_signal（可见的时间/金钱/风险；不知道就留空）
exact_excerpt（原文定位）
missing_information
```

Observation 层不设置 `latent_need`、`product_idea` 或 `market_score` 字段，从结构上阻止过早解释。

### 3.3 受控综合桥梁

桥梁同时读取已冻结的 `PrincipleModel` 和 `ObservationCard`，但输出只能叫 `NeedHypothesis`，不能叫“已发现需求”。

每个 `NeedHypothesis` 必须包含：

1. 目标人群与具体情境；
2. 从状态 A 到状态 B 的转变；
3. 直接支持它的 Observation ID；
4. 第一性原理映射；
5. 至少一个不需要该需求也能解释观察的替代解释；
6. 当前 workaround 及其可见成本；
7. 使用者、付款者和决策者是否相同；
8. 当前证据等级；
9. 仍缺少什么；
10. 最便宜的下一步证伪方法；
11. 明确淘汰条件。

### 3.4 解决方案能力库是下游第三流

领袖判断、新模型、跨领域概念和技术发布并不是需求证据。它们可以进入独立的 `CapabilityLibrary`，但只有在 `NeedHypothesis` 已经形成之后，才允许用于搜索解决方式。

顺序必须是：

```text
先形成问题假设
→ 再查询有哪些能力可以解决
→ 生成 SolutionHypothesis
```

禁止反向执行：

```text
先看到新技术
→ 再去网络中寻找能为它辩护的抱怨
```

## 4. 权限与认知分工

| 角色 | 可以做什么 | 不能做什么 |
|---|---|---|
| 原则建模器 | 推导稳定结构、列反例 | 看每日 feed、选择产品 |
| 观察记录器 | 忠实抽取现实事实 | 推断潜在需求、提产品 |
| 综合器 | 建立可证伪的需求假设 | 提升证据等级、宣布市场成立 |
| 解决方案设计器 | 对已形成的问题假设生成方案 | 用技术热度证明需求 |
| 验证器 | 检查外部行为和实验结果 | 用模型评分代替真实结果 |
| 策略引擎 | 根据真实证据推进状态 | 自由解释证据、扩大权限 |
| Javen | 决定外部联系、公开承诺、交易和方向 | 无需逐条审阅低风险内部处理 |

关键原则：提出主张的模块没有权力批准自己的主张。

## 5. 从观察到交易的状态机

```text
O0 原始观察
 ↓ 原文和情境可追溯
H0 问题假设
 ↓ 多个独立观察或清晰 workaround；仍不等于需求成立
H1 值得核对
 ↓ 真实对象付出时间或提供具体资料
C 承诺
 ↓ 在真实任务中获得首次结果
U 使用
 ↓ 发生可核验交易
P 付款
 ↓ 重复使用、续费或再次交易
R 留存
```

状态只能被相应的外部证据推进：

- AI 评分、点赞量和讨论量不能推进到 C；
- 口头“我会买”不能推进到 P；
- 一次付款不能推进到 R；
- 没有新证据时，状态不得因时间或重复生成自动升级。

## 6. 第一个最小影子实验

### 实验目标

不是寻找“最佳商机”，而是验证双通道结构能否阻止旧系统的三类错误：

1. 把网络原话改写成 AI 自己的需求故事；
2. 用新技术反向制造需求；
3. 用内部完整度和可构建性冒充市场证据。

### 固定输入

使用 2026-07-27 已冻结的 42 条 pain 信号作为同一批观察材料。旧闭环输出保留为对照，不重新生成来改变基线。

### 步骤

1. 在不查看 42 条信号内容的前提下，冻结 `PrincipleModel v0.1`。
2. 观察记录器只生成 `ObservationCard`，不生成需求、产品和分数。
3. 对 ObservationCard 做原文回链抽查；任何不存在于原文的事实都退回。
4. 综合器读取两个冻结输出，产生 `NeedHypothesis`。
5. 每个假设必须带替代解释、缺失证据和淘汰条件。
6. 与旧闭环同批候选比较：分别标出“原始事实、AI 推断、技术方案、市场证据”。
7. 只生成下一步验证建议，不联系任何人、不发布、不开发、不收费。

### 通过条件

- 每条 Observation 的事实字段都能回到原文；
- Observation 中没有产品建议、潜在需求结论或市场评分；
- 每条 NeedHypothesis 都引用具体 Observation ID；
- 每条 NeedHypothesis 都包含替代解释与缺失证据；
- 没有任何候选被标成 C、U、P 或 R；
- 原则模型没有因为这一批帖子的内容被静默改写；
- 对比报告能明确指出旧候选中哪些句子是事实、哪些只是内部推断。

任一条件不满足，说明隔离机制尚未成立，不进入外部验证。

## 7. 对现有创新闭环的处理建议

### 当前不做

- 不修改冻结的 NORTH-STAR；
- 不关闭采集器；
- 不删除历史候选或报告；
- 不自动发送已有帖子；
- 不因为新设计出现就宣布旧系统失败或新系统有效。

### 暂时重新定性

- 采集器：现实观察候选来源；
- 领袖与技术 digest：能力库来源；
- GENERATE：创意组合器；
- 一夜代码尺子：可构建性实验；
- 内部 gate：格式、证据回链和实验可执行性检查；
- 商业探针：只有接触外部真实行为后，才属于需求验证。

现有闭环可以继续产生内部工件，但其输出在新系统中不得自动获得“发现真实需求”的标签。

---

## 8. 本版暂不决定的问题

- 第一性原理模型最终采用什么人类动机分类；
- 先服务个人消费者还是企业使用者；
- 选择哪些网络社区作为正式来源宇宙；
- 是否以及如何联系帖子作者；
- 第一个验证实验采用访谈、人工服务、预售还是其他形式；
- 是否修改正在运行的创新闭环代码；
- 是否需要多个模型或多个 Agent。

这些问题要在影子实验揭示实际误差后再决定，不能凭架构偏好提前复杂化。

---

## 9. 当前决策

1. 保留现有系统作为历史基线和原始信号来源。
2. 不把现有内部 gate 通过率解释为需求发现能力。
3. 新建双通道影子流程，先验证认知隔离是否真的成立。
4. 影子流程通过后，再单独提议第一次现实验证；外部联系、发布、承诺和收付款仍由 Javen 批准。
5. 在真实付款与留存之前，不使用“找到商机”“市场已验证”“闭环成功”等完成性表述。
