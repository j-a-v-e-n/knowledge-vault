# 来源与检索日志

本日志不是“全网穷尽证明”。它记录本轮为限定决策问题建立的来源宇宙、检索方向、对抗轮次、停止依据与缺口。

## 检索范围

覆盖主题：

- 商业机会的发现、创造与有效交易条件；
- 明示需求、隐性需求、Lead User、情境观察与偏好构造；
- 网络社区、投诉、评论、搜索和用户生成内容的用途与偏差；
- 购买意向、支付意愿、感知价值、信任、切换、满意和复购；
- B2B 组织采购与经济买家；
- 创业实验、早期样本偏差、假阳性与假阴性；
- 当前 Agent、Harness、长任务、评测、多 Agent 与真实工作边界；
- 提示注入、权限、对外营销与 broad US/EU 合规风险。

未覆盖到可直接落地的程度：

- 任何具体行业的完整竞争、渠道与定价；
- 所有平台条款；
- 所有国家和地区的法律、税务、许可与消费者保护；
- 真实客户访谈、付款、交付、退款、复购和留存；
- 用户身份、信誉和现有渠道资产的实证盘点。

## 对抗性检索记录

### 第一轮：寻找核心思想的直接反例

检索方向：

- 网络投诉和评论为什么不能代表市场；
- 早期采用者和 Product Hunt 类样本如何误导；
- MVP 与错误实验如何产生假阴性；
- 当前最强 Agent 在开放式赚钱任务中是否成功；
- AI 创业和“被动收入”承诺是否出现监管失败案例。

新增或强化的关键类别：

- 抱怨者与受害者之间存在系统性自选择；
- 早期测试样本可改变创业方向并造成错误终止；
- Agent 在开放式盈利中遇到身份、支付、CAPTCHA、判断和执行障碍；
- “AI 自动赚钱”本身是高风险营销主张，必须以证据约束。

处理结果：进入证据向量、身份门、外部结果门、权限门和宣传证据门。

### 第二轮：寻找遗漏的替代解释与架构级风险

检索方向：

- 隐性需求是否可能只是呈现方式造成的偏好；
- UGC 与社交数据的外部有效性；
- 多 Agent 的错误复合、状态不一致和成本；
- 长任务上下文、评测污染、坏任务和奖励黑客；
- 提示注入是否能靠输入过滤单独解决。

新增或强化的关键类别：

- Demo 可能共同创造偏好，因此必须记录干预；
- 评测本身可能损坏、污染或低覆盖；
- 多 Agent 增加协调面，不能默认更强；
- 提示注入不能靠分类器完全解决，必须限制攻击成功后的后果。

处理结果：进入干预记录、独立验收、外部终态检查、单 Agent 默认、最小权限和数据/动作隔离。

### 饱和复查

把以上新类别纳入后，又按“需求发现失败、购买替代解释、实验误判、Agent 长任务失败、开放网络攻击、对外营销责任”重新检索。新增材料继续落入已有类别，没有再出现需要改变总体骨架的新类别。

因此，停止理由不是“没有更多资料”，而是：

> 在本轮明确范围内，连续复查没有产生新的承重主张类别；新增来源只会加强、削弱或细化已有边界。剩余关键未知必须靠具体市场与真实行为实验取得。

本轮可以声称：

- 已覆盖设计所依赖的主要跨学科承重问题；

- 已完成具体司法辖区的合规审查。
