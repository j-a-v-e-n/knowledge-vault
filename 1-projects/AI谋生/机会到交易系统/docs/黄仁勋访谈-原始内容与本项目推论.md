- Harness 调优案例：<https://www.langchain.com/blog/tuning-the-harness-not-the-model-a-nemotron-3-ultra-playbook>

这是 NVIDIA 与 LangChain 联合产品发布语境中的访谈。它是一手观点来源，也是产品方陈述；不能当作独立市场研究。

## 访谈实际支持的判断

### 模型只是系统的一部分

访谈约 `01:24–02:13` 把可用 Agent 描述为模型与知识、工具、记忆、安全措施和迭代机制共同组成的系统。约 `18:22–20:20` 又加入运行环境、沙盒、隐私和访问控制。

因此，把 Harness 理解为“模型周围可设计、可积累、可评测的工作系统”是合理的。

### 通用前沿模型与专业系统互补

约 `08:50–12:32`，黄仁勋明确表示自己会从前沿模型开始；随后再为供应链、芯片设计等特定任务连接专业子 Agent、工具和专有知识。他也明确保留外部工具、顾问和外包的角色。

因此，访谈不支持“所有模型和能力都必须自建”。更准确的理解是：通用能力可以外部获得，定义组织差异的专有流程、数据、评测和改进循环需要由组织掌握。

### Harness 的效果必须由评测证明

约 `05:54–06:38` 讨论了 LangChain 的 Deep Agents 评测结果。官方调优案例进一步说明，改动集中在系统提示、工具描述和中间件，并通过执行轨迹与重复评测保留有效变化。

这证明的是特定模型在特定 Agent 评测中的系统调优效果，不证明商业需求、客户满意度或任何行业都能获得同样结果。

### 企业资产可能沉淀在系统层

约 `09:50–17:08`，访谈把专有知识、工作流、工具连接和持续改进视为企业专业能力的一部分。联合发布说明还列出记忆、工作流、轨迹、评测数据和 Harness 配置等资产。

对本项目而言，真正值得积累的不是某个模型名称，而是：真实观察、买家互动、失败反例、Offer、项目 Harness、评测案例、交付结果和交易记录。

## 解说稿中需要降级的部分

### “核心智能绝对不能外包”过于绝对

黄仁勋确实反对把定义个人、公司或国家的专业智能完全交给第三方，但同一段访谈也支持继续使用前沿模型、外部工具、顾问和外包。应理解为掌握控制权与改进权，而不是拒绝一切外部能力。

### “所有技术拼图已经齐全”是发布语境中的主张

访谈结尾用强烈措辞推广联合蓝图。这能证明发布方的定位，不能证明安全、可靠性、组织采用和商业回报问题已经普遍解决。

### “越用越聪明”不能理解为自动学习保证

访谈描述的是通过使用、反馈、评测、Harness 调优与后训练构成的飞轮。没有证据表明一个普通 Agent 只要持续运行就会自然改进。

### 访谈没有提供商机发现方法

它没有证明网上抱怨等于需求，也没有解释隐性需求、支付意愿、销售、定价或交易验证。把 Harness 用到商业发现，是本项目在访谈之外提出的设计，必须由真实市场结果验证。

## 对本项目的有限启发

访谈可以支持一种工程选择：使用可替换模型，把真正的长期资产放在证据、流程、工具、权限、评测与改进记录中。

它不能替本项目回答“谁愿意为什么付钱”。这只能由目标买家的外部行为和交易回答。
