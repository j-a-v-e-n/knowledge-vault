# 长期能力投资地图与训练路线

状态：当前战略结论；基于本轮从零检索的一手来源、原始访谈字幕复核和反方研究。不是对未来的确定预测，也不是某个暑期课程表。

## 最终收束

Javen 的长期主下注不应写成“学 Agent 架构”，而应写成：

> **以可靠自主系统为技术主轴，以需求、交易和结果验证为商业主轴，把领域数据、真实失败评测、集成权、客户关系与收益权沉淀为可控制资产。**

Agent/Harness 是这套能力的执行层。它值得深学，但通用框架、通用记忆、通用编排或通用 trace 面板本身，不是默认的长期产品或护城河。

这个答案不依赖“有某种人类技能永远不会被 AI 替代”。判断标准改成：一项能力是否能让人机系统更快接触现实、分辨错误、完成结果、取得反馈，并把反馈转化成下一轮仍由 Javen 控制的资产。

## 为什么原项目后来变大

最初的问题只有“长期学什么”。继续推理后发现，单列技能会漏掉三个决定性问题：

- 学到的能力有没有在真实环境中产生结果；
- 结果能不能带来现金、反馈或控制权；
- 所谓资产是不是仍依赖一次一结的本人劳动。

因此项目才扩成当前三层：长期能力地图、现金流与资产组合、单个低成本现实实验。扩展是为了让长期判断经受现实反馈，不是把机会筛选或治理变成新北极星。

## 当前证据给出的边界

### 通用 Agent 基础设施会继续平台化

[AWS AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)、[Microsoft Foundry Agent Service](https://learn.microsoft.com/en-za/azure/foundry/agents/overview?view=foundry-classic)、[Google Vertex AI Agent Engine](https://cloud.google.com/vertex-ai/generative-ai/docs/reasoning-engine/overview) 和 [OpenAI Agents 工具](https://openai.com/index/new-tools-for-building-agents/)已经把 runtime、memory、identity、工具、sandbox、observability、evaluation 或 orchestration 的大量通用部分纳入平台。由此推断，熟练调用某个框架 API 会折旧；理解这些机制为何存在、怎样验证和怎样迁移，仍有价值。

### Agent/Harness 仍是重要系统工程

[NIST AI Agent Standards Initiative](https://www.nist.gov/artificial-intelligence/ai-agent-standards-initiative)把身份、授权、互操作、安全和评测列为仍需研究与标准化的问题。这支持“可靠 Agent 系统仍有大量未解决工程”，但不支持“做一个通用安全或评测产品就一定有人付款”。

[LangChain/NVIDIA 技术案例](https://www.langchain.com/blog/tuning-the-harness-not-the-model-a-nemotron-3-ultra-playbook)显示，固定模型后，基于 trace 改工具描述、上下文位置、middleware 和循环控制可以改善任务表现；同一文章也明确写出 Harness 有能力上限，权重中没有的能力仍需更合适模型或 post-training。厂商同时销售相关模型、框架和运行平台，结果只能视为有利益冲突的案例，不是普遍规律。

### 真正稀缺更靠近领域和现实接口

[NIST 制造业数字孪生项目](https://www.nist.gov/programs-projects/digital-twins-advanced-manufacturing)和[机器人新兴技术项目](https://www.nist.gov/programs-projects/performance-emerging-technologies-robotics)把异构设备、数据、测量、互操作、验证、不确定性、安全与中小制造商集成能力列为现实难点。它们与 EE/ML/Controls 邻接，支持把“可靠自主系统与真实世界集成”保留为长期技术期权；它们不证明当前某个工厂会向 Javen 付款。

[Stanford AI Index 的经济章节](https://hai.stanford.edu/ai-index/2026-ai-index-report/economy)显示组织 AI 采用在扩张，但 Agent 在大多数业务功能中的部署仍处早期。早期意味着存在试验空间，也意味着没有足够证据把任何通用 Agent 方向当作已成熟市场。

## 应积累的能力组合

### 现实发现与交易

要能把公开线索、目标假设、问题确认、主动兴趣、付款、验收和复购分开。训练产物不是“想出好 idea”，而是一个诚实探针、原始回应、停止决定和完整成本记录。

如果长期只有内部分析、Demo 和 AI 自评，没有真实对象的行为反馈，这项能力没有通过现实验证。

### 工作流、责任与经济性建模

要能把真实工作拆成状态、输入、权限、动作、异常、人工判断、验收和责任，并同时描述谁创造价值、谁拥有预算、谁承担错误、谁取得收益权。

如果模型效果改善但客户结果、责任边界和全成本仍说不清，就不能把技术进步写成商业进步。

### Eval、测量与失败归因

先定义外部结果和失败条件，再建立可重复任务、held-out 案例、轨迹、回归、成本与延迟记录。关键能力是从证据判断失败来自模型、上下文、数据、工具、权限、流程还是根本不存在的需求。

如果改动只在调试时看过的案例上有效，或换一个环境就失效，当前方法应被判定为过拟合。

### 可靠 Agent/Harness

深学工具合同、上下文工程、状态与记忆、确定性门禁、身份和最小权限、sandbox、预算、重试、停止、人工接管、观测、恢复和供应商迁移。框架可以用来加速，但学习验收标准是：换框架或换模型后仍能重建机制并解释差异。

如果托管平台能更便宜地提供同等通用能力，应使用平台并停止重复造轮子；只保留与领域结果直接相关的差异层。

### 模型选择与领域适配

模型不是可以任意互换的零件。先用足够强的现成模型得到任务上限，再根据稳定 Eval 依次检查数据、检索、工具、确定性规则和 Harness。只有当稳定 Harness 下仍出现可重复的权重级缺口，并且拥有合法训练数据、隔离测试和足够使用规模时，才把微调或 post-training 升为主动作。

最新事实适合放进检索或工具；每次必须遵守的规则适合放进确定性代码；模型与工具的交互不匹配适合改 Harness；稳定行为能力缺口才可能进入训练。

### 控制、估计与真实系统

继续积累控制、估计、优化、信号、传感、嵌入式或边缘系统、故障与安全验证，并把它们与 Agent 的 Eval、权限和人工接管连接起来。长期目标不是“做 Physical AI”，而是能在具体设备、具体数据和具体责任边界内，让自主系统安全地产生可测结果。

如果长期拿不到授权设备、数据、领域合作者或现场问题，这条路线只能保留为学术能力，不能继续假装已经形成商业资产。

### 数据、集成权与分发

代码容易复制，合法的真实失败样本、领域 Eval、设备适配器、客户工作流、直接关系、运行权和合同收益权更接近可积累资产。所有资产主张都要回答：谁拥有、能否迁移、能否重复使用、是否降低后续边际成本、模型或平台更换后是否还存在。

## 与现有项目的关系

### 机会到交易线

它是现实发现、诚实外联、交易语义、单位经济和资产化判断的训练场。CA012650 建筑基准核对只是低成本问题发现样本；它不是长期领域选择，也没有证明需求、付款或交付。

### 投研纪律线

它是 paper-only、human-final 的可靠性与证据训练场：练确定性风险门、候选身份、回归、恢复和不自证完成。当前候选完整测试失败，所以它既不是运行中的系统，也不是收益资产。

### EE/ML/Controls 现实系统线

未来应从实验室、课程团队、工程合作者或经授权的小型现场取得一个真实接口，把传感、控制或优化任务与 Agent 工具、Eval、故障注入和人工接管接起来。这是长期技术期权，不需要立即伪装成现金项目。

## 训练路线

### 先建立跨模型、跨 Harness 的失败诊断实验

选一个可重复且有外部验收的任务，固定输入、工具和 Eval；建立强模型最小系统基线，再分别改变模型与 Harness。每次只改一个可归因变量，保存轨迹、失败簇、成本和回归。目标是学会判断“该换模型、改系统，还是停止任务”，不是刷某个榜。

### 再嵌入真实领域

取得授权工作流样本后，把领域数据、工具、权限、确定性规则和人工升级加入同一实验；用未参与调试的新案例和环境变化检验泛化。没有真实责任人和结果反馈时，不进入 post-training。

### 同时运行低成本市场探针

技术实验和需求实验并行。合理问题假设足以支持一次低风险、诚实、可停止的核对；对方确认问题或主动请求下一步之后，才升级定制诊断；付款者、交付和全成本成立之后，才升级交易；复购、迁移和创始人依赖下降之后，才讨论资产。

### 让每个项目留下可迁移残值

即使候选失败，也应留下经过授权的失败分类、Eval、工具合同、成本记录、停止理由和可迁移方法。若一次试验只留下无法复用的页面或大量治理文档，就没有完成长期能力投资。

## 什么会推翻当前建议

- 强模型进步使定制 Harness 长期不再带来可测增益，且平台能以更低全成本提供可靠结果；
- 当前学习只在公开 benchmark 或内部样本上有效，无法迁移到未见案例；
- Javen 无法取得任何真实领域接口、授权数据或责任人反馈；
- EE/Controls 方向长期只停留在名词，没有设备、测量、仿真或现场产物；
- 反复技术成功但目标不愿改变流程、投入行为或付款；
- 所谓资产仍完全依赖 Javen 逐项判断和交付。

这些反证出现时，应改模型、改领域、降级为现金服务或停止，不为维护既有叙事继续投入。
