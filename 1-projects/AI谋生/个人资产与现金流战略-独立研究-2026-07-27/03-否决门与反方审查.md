# 否决门、证据阶梯与反方审查

## 为什么不做一个总分榜

需求强不能抵消违法，增长快不能抵消负的全成本，产品漂亮不能抵消无人付款。把一切相加会制造伪精确。

采用顺序：

> 否决门 → 证据等级 → 最弱关键项 → 风险集中 → 所属账户 → 是否增加投入

只有已经通过相同生存门槛的候选，才值得做有限的相对比较。

## 先过否决门

### 所有项目的生存门

- 所需数据、内容、软件、身份和行动权限能够合法取得。
- 最坏损失、责任和外部影响在预先定义的承受边界内。
- 存在一个明确用户、重复问题和当前替代做法，而不只是技术演示。
- 能指出潜在付款者、预算来源和结果衡量方式。
- 能设计一个比完整开发更便宜的外部反证实验。
- 已完成大厂与垂直 incumbent 检索；如果对方加入原生菜单或套餐，仍有独立付款理由。

未过任一项，只能拒绝或暂停研究，不能靠其他优点补偿。

### 升级为资产候选的附加门

- 有合法、可持续的控制对象：直接客户关系、合同、IP、获许可数据、运行权或物理接入之一。
- 痛点与收益具有重复性，而不是一次性新鲜感。
- 存在减少创始人边际判断和劳动的可测试机制。
- 模型、平台、渠道或操作者更换后，核心状态可以迁移或恢复。
- 收益捕获不是单靠某个平台临时流量或补贴。

一个项目可以不过资产门但仍是好现金工作；这不是失败，只是不能误分类。

## 证据阶梯

| 阶段 | 可接受证据 | 不足以升级的信号 |
|---|---|---|
| 未知 | 尚无直接观察 | AI 分析、创始人确信 |
| 主张 | 访谈、行业材料、用户口头兴趣 | 点赞、搜索热度、礼貌性认可 |
| 行为 | 用户投入时间、真实资料或完成有摩擦的试用 | 无成本注册、围观演示 |
| 交易 | 按接近现实条件付款、押金或作出有约束力承诺 | 友情订单、免费、平台补贴 |
| 重复 | 独立客户复购、续费或持续使用 | 靠新鲜感、折扣或创始人无限代运营 |
| 可运营 | 全成本为正；替代操作者可运行；迁移与恢复经过实际测试 | 一份架构图、代码完成、AI 自评通过 |

机会的阶段不得高于需求、付款、复购与全成本中证据最弱的一项。

## 事实、推断、未知必须分栏

每张候选卡都必须回答：

| 类型 | 写什么 | 示例 |
|---|---|---|
| 事实 | 有日期、对象和来源的直接观察 | 某付款人按现实价格续费；某次运行产生已记录故障 |
| 推断 | 事实对机制或未来的解释 | 该流程可能存在切换成本 |
| 未知 | 能推翻机会但尚未验证的变量 | 去掉人工代运营后是否仍能达到验收标准 |

## 定性审查表

每项只记录“有利、混合、不利、未知”，并附证据，不填想象出来的概率。

| 维度 | 最强支持证据 | 最强反方问题 |
|---|---|---|
| 需求 | 用户已有高成本替代并主动寻找办法 | 需要结果，还是只觉得演示有趣？ |
| 支付 | 真实预算按现实条件成交 | 是真正付款，还是友情、积分、折扣或补贴？ |
| 复购 | 去除补贴后仍重复使用 | 痛点会重复，还是一次性新奇？ |
| 控制 | 合同、合法 IP、获许可数据或直接关系 | 平台或竞争者明天能否复制或拿走？ |
| 全成本 | 扣除获客、模型、托管、支付、退款、支持、税务、人工复核和创始人时间后仍成立 | “利润”是否只是没有给自己的工时定价？ |
| 维护 | 每单位故障和人工介入随重复交付下降 | 模型、网页、API 或客户流程变化一次会造成什么？ |
| 平台集中 | 客户、数据与收入可导出和转移 | 是否被一家模型、渠道、支付或平台卡住？ |
| AI 商品化 | 价值落在专有流程、数据、信任、权限或现实行动 | 下一代模型会不会直接内置主要功能？ |
| 法规与责任 | 数据、内容、隐私和用途权利已确认 | 是否触及金融、就业、教育、医疗或其他高影响决定？ |
| 资本 | 投入只释放到下一个外部证据节点 | 在证明付款前需要多少不可逆投入？ |
| 可迁移 | 模型、渠道、数据与状态迁移实际演练通过 | “理论可迁移”是否只是架构宣称？ |
| 创始人依赖 | 有运行状态、手册、验收与替代操作者 | 创始人停止判断后，收入或系统是否停止？ |
| 失败残值 | 有明确的其他使用者、合法用途或买家 | 剩下的是可控资产，还是无人维护的代码？ |
| 到证据距离 | 最便宜反证可执行且能观察 | 是否用开发来逃避销售或现场观察？ |
| 大厂碰撞 | 平台增强降低交付成本，但客户特有流程、数据、责任或现场价值仍在 | 原生产品加入一个菜单项后，谁还会为什么单独付钱？ |

## 状态而不是名次

- **拒绝**：违法、权利不可得、损失不可承受或责任无边界。
- **暂停研究**：关键变量未知，且取得证据的当前成本过高。
- **探索**：核心假设可以由便宜的外部实验推翻。
- **验证**：已有真实交易，但复购或全成本未知。
- **现金流工作**：全成本为正，但仍高度依赖创始人。
- **资产候选**：复购、控制与可迁移开始成立，创始人依赖在下降。
- **可扩张资产**：不同客户或批次重复成立，运营与风险边界经过验证。

## 对“自动产生价值”的强反方

### 自动运行不等于自动获客

AI 可以降低生产成本，但客户注意力、信任、采购、合同和售后仍可能成为主要成本。供给同时变便宜时，售价可能降得比成本更快。

### 自动运行不等于拥有收益权

一个系统能工作，不代表你拥有数据、客户、渠道、IP 或未来现金流。平台账号和流量不是稳固产权；控制权和合同决定谁捕获价值。

### 资产也不会永久无维护

模型、API、平台政策、法规、客户流程和竞争都会变化。更现实的目标是“边际运营负担可测地下降并受边界控制”，不是无人治理的永动机。

### Agent 技能可能只是暂时脚手架

厂商已经把通用部署、记忆、编排、身份、可观测与评测纳入平台。仅会搭通用 Harness 的价值会被压缩；与具体业务结果、垂直评测、现实权限和故障证据结合，才更可能成为模型进步的互补品。

### “大厂现在还没做”不是护城河

现有平台可以利用已有用户、账户、数据和套餐吞并相邻功能；垂直系统记录商也能把 AI 放进客户当前界面。必须先查对方当前功能和路线，再回答：对方升级后，是降低我们的成本，还是消灭我们的收入？详细边界见《大厂边界与小公司位置》。

### 创始人代运营既是风险也是学习机制

探索期亲自处理异常是获取隐性流程和失败数据的必要方式。问题不是早期有人参与，而是随着重复交付，人工介入是否下降；如果不下降，就应诚实归入自动化自雇。

## 风险簇审查

组合不能只按行业名称分散，还要检查隐藏依赖：

- 相同模型提供商；
- 相同云、应用商店或内容平台；
- 相同获客渠道和付款人；
- 相同数据来源与权限；
- 相同监管类别；
- 相同创始人注意力和故障处理能力。

多个依赖同一内容平台的机器人不是多元化，而是同一个政策下注。

## 预先写下的停止信号

- 找不到目标用户，或用户不愿付出任何行为成本。
- 在约定验证窗口内没有现实条件下的付款承诺。
- 去掉折扣、补贴、代运营或新鲜感后，使用和续费消失。
- 计入全部成本后仍为负，且没有一个能单独验证的修复变量。
- 客户增加时，人工介入、事故或支持成本不降反升。
- 单个平台变化可以摧毁业务，且迁移成本超出风险预算。
- 大厂或垂直 SaaS 已把核心结果放入现有套餐，而项目仍没有不同的付款理由。
- 必需的数据、版权、隐私、执照或行动权无法取得。
- 获得下一项关键证据需要超过预设的时间、现金或责任上限。
- 所谓转向没有形成新的可证伪假设和新的停止条件。

更快关闭错误项目是组合学习的成功，不是羞耻。当前研究也支持把真实实验和理性退出视为提高后续质量的机制：[Management Science](https://pubsonline.informs.org/doi/10.1287/mnsc.2021.4209)、[NBER](https://www.nber.org/papers/w34755)。

## 常见候选的最强攻击

| 候选 | 最强攻击 | 只有满足什么才升级 |
|---|---|---|
| 通用 AI wrapper/copilot | 模型或既有软件快速内置，切换成本低 | 垂直数据、深集成、结果责任或合同渠道 |
| AI 内容农场 | 无限供给、平台政策、版权与透明度风险 | 原创 IP、第一方受众、直接分发、非广告收入 |
| Prompt、模板、课程 | 易复制、折旧快、复购弱 | 可信品牌或高价值服务入口 |
| 快速开发的微型 SaaS | 制作便宜但获客、支持、安全和维护未变便宜 | 重复 B2B 痛点、现实付款、复购、可控分发 |
| AI 自动化 Agency | 定制和异常使其成为高杠杆自雇 | 标准化、合同化、运行手册化，人工介入下降 |
| 通用客服机器人 | 厂商和既有 SaaS 会捆绑 | 连接专有系统、承担可测结果、可靠人工升级 |
| AI 商店或自动套利 | 隐藏广告、库存、退款、平台与法律成本；易出现误导收益宣传 | 独立需求、全成本利润、合法权利、可迁移渠道 |
| 金融、招聘、教育决策 | 高错误成本与监管责任 | 明确权限、独立验证、审计、人类最终责任和合规能力 |
