  # Method A: TROIKA-lite Summary
2026-05-20

## 设计思路

Method A 是 paradigm benchmark 的信号处理基线，不追求 SOTA，而是为 method C 提供同一 pipeline 下的对比起点。

Pipeline: PPG bandpass → FFT → coef-normalized spectral subtraction → HR tracking peak selection → BPM

## 关键决策

**1. coef normalization**

Sanity 发现 PPG/accel PSD scale 差 1500×，λ=1.0 时 spectral subtraction 等于 no-op。改用 HR 频段内最小二乘回归得到 coupling coefficient，缩放后再减。Subject 01 MAE: 24.6 → 20.9。

**2. HR tracking + cold start + self-correction**

发现 cleaned 频谱内多个能量相近 peak，max-peak selection 对噪声敏感。引入上一窗 HR 约束 (±15 BPM)，加 cold start (前 N 窗不约束) 和 self-correction (band 内峰 < global max × T 时 fallback)。Subject 01 MAE: 20.9 → 13.6。

## 简化部分

按 proposal §4 砍掉 M-FOCUSS + 双通道融合。理由: controlled comparison 要求 method A/B/C 共享 pipeline，M-FOCUSS 实现门槛超出本科课程时间预算。

## 结果

Overall MAE: **15.11 BPM** (11 subjects, subj09 在 Udacity 镜像缺失)
- 6 subjects < 10 BPM
- 3 subjects 13-17 BPM
- 2 catastrophic outliers: subj02 (31), subj10 (59)

参数 N=10, T=0.5, J=15, λ=1.0

## 留给 method C 的研究空间

Method A 两类失败:
1. **Peak ambiguity** – cleaned 频谱多峰，max selection 选错
2. **Tracking lock-in** – cold start 后锁错 basin 救不回 (subj02, subj10)

Method C 测试 LLM 能否:
- 看频谱多峰 + HR history 选对
- 调 λ 间接 rescue lock-in 窗口

这是 paradigm-level 对比 (LLM 推理 vs explicit state space)，不是精度竞赛。
