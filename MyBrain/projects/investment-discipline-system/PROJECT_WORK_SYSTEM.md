# 项目工作系统｜本项目实例

## 它是什么

项目工作系统是一层“如何共同推进项目”的基础设施，不是投研策略本身。它负责让人和 AI 在较长时间里保持同一张地图：

- 目标和边界是什么。
- 当前真实状态是什么。
- 下一步可执行动作是什么。
- 哪些决定已经确认，为什么确认。
- 哪些结论有证据，证据有什么限制。
- 谁可以做什么，什么需要人确认。
- 一轮工作如何开始、如何结束、如何交接。

## 当前实例的最小组成

| 内容 | 文件 | 作用 |
| --- | --- | --- |
| 项目目标 | PROJECT_CHARTER.md | 规定为什么做、做什么、不做什么 |
| 当前状态 | STATUS.md | 防止把过去、现在和未知混在一起 |
| 工作任务 | TASK_BOARD.md | 把方向转成当前可执行工作 |
| 路线图 | ROADMAP.md | 保存顺序、依赖和未来方向 |
| 长期决定 | DECISIONS.md | 防止重要判断在长任务中丢失 |
| 外部证据 | RESEARCH_INDEX.md | 记录来源、结论和边界 |
| AI 方法 | AI_COLLABORATION_METHOD.md | 规定如何研究、设计、搭建和验证 |

## 运作协议

开始时，恢复状态；执行中，围绕一个任务推进并保留中间产物；结束时，更新状态、证据、决定和下一步。若发现需要改变项目方向，先停下来讨论，不把方向变化藏在实现细节里。

## 通用化边界

稳定、重复、与具体项目无关的部分，未来可以抽象为通用项目工作系统；例如状态格式、任务状态、决定记录、研究登记、交接协议和验收协议。

只属于投研系统的内容留在本项目中；例如市场规则、投资风险、数据质量、回测方法和交易权限。

## 为什么现在不直接做成完整产品

通用系统的真实需求还没有经过多个项目验证。当前先用一个真实项目运行这套最小结构，观察哪些文件真正被读取和更新、哪些字段造成负担、哪些缺口会导致返工，再决定是否抽象、删减或产品化。

## 未来可抽象的能力

- 新建项目时自动生成项目空间和初始文档。
- 读取状态后生成工作简报。
- 将任务、决定、证据和变更相互链接。
- 在任务结束时检查是否更新了状态和验收证据。
- 为不同项目挂载不同的规则、工具权限和验证器。
- 与版本控制、备份和其他协作工具连接。

这些属于未来方向，当前不代表已经实现。
