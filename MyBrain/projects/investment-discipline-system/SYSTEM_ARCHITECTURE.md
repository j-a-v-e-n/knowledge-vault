# 可执行系统架构｜投研纪律系统

## 架构目标

把系统组织成“证据产生、人工决定、确定性约束、纸面执行、审计复盘”几个相互隔离的层。AI 可以帮助研究和建议，但不能直接把自然语言变成交易。

## 核心边界

| 层 | 负责什么 | 不允许什么 |
| --- | --- | --- |
| 数据层 | 获取、保存、校验和版本化行情、新闻和其他来源 | 用未记录来源的数据作决定 |
| 证据层 | 把事实、推断、假设、未知、反例和来源组成证据包 | 把摘要或模型自信当成事实 |
| 建议层 | 生成行动、等待、不交易、条件和失效条件 | 直接提交订单 |
| 人工决定层 | 记录接受、拒绝、延后或修改，以及理由和情绪状态 | 无记录地临场改变决定 |
| 风险闸门 | 确定性检查额度、频率、失效条件、证据时点和规则版本；买入额度由订单数量、价格和账户现金计算 | 被 AI 或订单请求绕过 |
| 执行层 | 当前只执行纸面操作，并把结果返回给账本 | 连接真实交易端点或自动使用真实资金 |
| 账本层 | 追加记录所有输入、输出、决定、拦截、执行和复盘 | 事后静默覆盖历史记录 |
| 复盘层 | 与预先指定的基准并列比较，记录偏差和失效 | 只展示盈利或单一指标 |

## 主要状态转换

研究想法 → 证据包 → 分析建议 → 人工决定 → 风险检查 → 纸面接受或拒绝 → 纸面复盘

每个转换都生成带有时间、来源、版本和前序事件摘要的账本事件。任何失败路径也必须进入账本。

## 组件接口

- DataSource：按给定时点返回来源快照、元数据、缺失值和哈希；快照中的数据可见时间必须能独立审计。
- EvidenceBuilder：生成结构化证据包，明确事实与推断。
- RecommendationEngine：生成建议和不确定性，允许不交易。
- DecisionRecorder：保存人的最终选择、偏离原建议的状态、情绪说明和复盘承诺。
- RiskGate：只接受结构化输入，返回允许或拒绝及确定性原因。
- PaperExecutor / ExecutionAdapter：模拟订单、成交、持仓和现金变化，返回结构化结果，不具备真实交易权限。
- Ledger：追加式写入、链校验、查询和导出。
- ReviewEngine：读取冻结的决策和结果，与基准计算并列复盘。

组件之间传递结构化对象，不传递“请相信上一段文字”的隐含状态。

## 权限模型

- AI：可读取项目资料和公开来源，可生成研究、文档、代码和纸面建议。
- 人：拥有最终投资决定权，拥有修改核心项目目标和规则的权力。
- 确定性闸门：拥有拒绝越界纸面操作的权力。
- 真实券商适配器：当前不存在；未来若增加，必须与纸面适配器分离，并默认关闭。

## 数据与时间模型

- 每个输入必须有来源、来源时间、获取时间、数据版本和快照哈希。
- 决策使用的证据包必须证明其信息不晚于决策时点。
- 复盘使用的结果数据必须与决策数据分开冻结，不能回写决策输入。
- 修订后的来源建立新快照，不覆盖旧快照。
- 缺失、冲突、延迟和异常数据进入失败路径，而不是被静默填补。
- 风险计算使用闸门时点冻结的账户状态；执行层失败不能回写成闸门拒绝或成功成交。

## 部署方向

当前采用本地优先、文件可读、标准库可运行的原型。等数据、执行和复盘接口稳定后，再决定是否引入数据库、网页界面、后台服务或云运行。

## 验证层次

- 单元验证：规则、时间边界、状态转换、哈希链和数据校验。
- 端到端验证：从研究想法到纸面复盘。
- 反例验证：越权、未来信息、缺失数据、重复事件、修改建议和账本篡改。
- 纸面运行验证：连续样本、基准对照、成本和执行偏差。
- 人工验收：确认系统输出是否符合真实协作目标和使用习惯。

## 当前未实现

- 新闻与基本面来源的快照化。
- 可交易资产的复权和公司行动处理。
- 多资产组合和持仓状态。
- 真实纸面券商 API。
- 外部数据源适配器及正式数据许可核验。
- 外部纸面券商适配器、订单对账和故障恢复。
- 运行监控、提醒和界面。

## 当前原型模块映射

- prototype/discipline_system.py：证据包、建议、人工决定、风险闸门、纸面事件和追加式账本。
- prototype/contracts.py：供应商无关的数据快照和执行结果契约；当前只有本地纸面执行适配器。
- prototype/backtest.py：开发/留出历史检验、交易成本、基准和无未来信息审计。
- prototype/paper.py：本地现金、持仓、纸面成交和市值。
- prototype/workflow.py：把证据、决定、闸门和纸面账户串成一个不可跳过中间层的流程。
- prototype/run_real_data_case.py：真实来源纸面案例。
- prototype/run_real_data_backtest.py：真实来源历史检验案例。
- prototype/run_paper_suite.py：连续纸面运行的分支覆盖和账本复盘案例。
- prototype/research_run.py：把历史检验结果写入统一研究运行账本事件。
- prototype/run_unified_prototype_case.py：受控夹具的历史检验—纸面执行—复盘统一案例。
- prototype/run_real_data_unified.py：保存的 FRED 来源统一研究案例。
- prototype/run_contract_faults.py：数据/执行契约的本地故障注入案例。

这些模块是可运行的原型，不等于已经完成生产级数据、部署、权限和券商适配。
