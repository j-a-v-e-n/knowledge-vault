# 既有系统独立审计｜2026-07-25

## 裁决

截至审计快照 `984c1446dbd6ebfb6fdec3bc9a88afdaad742216`，既有代码只能证明“可运行、可复查的纸面管线原型”，不能证明“个人长期可用产品”或“不可绕过的纪律系统”。

审计者与构造者分离。审计在独立临时副本执行，没有修改项目文件。原有 `23` 个单元测试和全部 runner 均通过，但对抗探针击穿了测试未覆盖的核心不变量。因此，原有绿灯只能保留为“旧路径仍可运行”的回归证据，不能继续作为 MVP 完成证据。

## 可复现的反例

### 闸门批准对象与执行对象不一致

旧工作流只比较闸门订单和执行请求的 `order_id`，没有绑定方向、标的、数量和价格。审计探针证明：

```text
gate_allowed=True
approved_action=buy
executed_side=sell
```

任何调用方还可以直接构造 `GateResult(True, ())`；频率上限依赖调用方提交的历史订单。旧闸门不是不可绕过的权威边界。

### “无未来信息”验证接受事后下载的数据

旧 `DataSnapshot.validate_for_decision` 不检查 `retrieved_at`。审计探针中，决策时间为 `2024-01-02`、获取时间为 `2026-07-21`，验证仍返回无错误。

旧真实来源 runner 还把 `retrieved_at` 硬编码为 `2026-02-04`，但与结果哈希匹配的本地文件已经包含 `2026-07` 的记录。它证明的是“当前文件可以回放”，不是“该历史时点真的可知”。

旧回测的日期审计使用 `zip()`；当一侧为空时会静默返回通过：

```text
decision_dates=('2024-01-01',)
visible_through_dates=()
no_future_information=True
```

### 哈希链不能证明历史完整

旧 JSONL 验证器只校验现存记录的内部链。删除尾部后仍通过；事件时间倒序仍通过；完整重写整条链也没有独立锚点可发现。

真实旧账本中还存在“运行完成时间早于运行开始时间”的顺序，而校验器仍返回有效。

### 账户状态和账本不是原子提交

旧 `PaperAccount` 只存在于进程内。重启后订单幂等键、现金和持仓不能恢复。模拟账本写入失败时，账户已经扣款并生成 fill，却没有对应审计事件：

```text
error=simulated ledger failure
cash_after_error=900
fills_after_error=1
```

### Git 恢复不能重跑核心真实来源案例

从 Git 归档恢复后，单元测试仍通过，但三个 FRED runner 因 `prototype/data/raw/*.csv` 被 `.gitignore` 排除而失败。存在 GitHub 远端不等于关键运行可以恢复。

## 旧原型实际实现边界

- 没有统一应用入口，只有硬编码 runner。
- AI 建议和“人工决定”都是源码内构造的数据类，没有真实录入入口。
- `DataSource` 与 `ExecutionAdapter` 只有协议或本地实现，不是已验证的可替换主链。
- 回测是固定移动平均演示，没有 point-in-time vintage、总回报、公司行动、退市、生存者偏差、多重试验控制或封存的留出集。
- 复盘由 runner 手工填写，没有到期、逾期、校准、归因或反馈状态。
- 没有 CI、依赖/运行环境声明、数据库迁移、恢复流程或长期账户状态。

## 状态纠正

以下旧声明全部撤回，直到新的冻结验收合同提供独立证据：

- “确定性风险闸门不可绕过”
- “真实来源无未来信息审计通过”
- “连续运行保留长期状态”
- “账本可以证明完整历史”
- “真实来源统一研究链已成为可用产品”
- “个人纸面 MVP 已完成”

## 强制进入下一版的证明义务

1. 闸门批准必须绑定完整、规范化后的订单意图哈希；执行器只消费数据库中未使用且完全匹配的批准。
2. 频率、现金、持仓、风险暴露和幂等状态只能来自权威持久状态。
3. 数据快照保存原始内容、真实来源、查询、获取/观察/可见时间和哈希；历史决策不得把事后当前版本冒充当时快照。
4. 策略必须通过 prefix-causality 测试：追加未来数据后，过去信号逐值不变。
5. 账户状态变化与审计事件必须在同一数据库事务中提交。
6. 事件表禁止修改/删除，具有序号、发生时间、写入时间、哈希链和独立尾部锚；尾删、乱序和重写必须被发现。
7. 每轮使用不可变 run manifest，绑定代码、配置、数据、策略、模型/Prompt、风险规则、账户快照和终态。
8. 从独立目录恢复后，不依赖被忽略的私有数据即可重跑核心验收；关键私有运行另有带哈希备份。
