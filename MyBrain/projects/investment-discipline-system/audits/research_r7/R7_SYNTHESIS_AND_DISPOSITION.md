## Decision disposition by topic

### RS-01 — research sufficiency

Conditionally adopt for high-impact research:

- distinguish `finite_frozen_corpus` from `open_dynamic_web`;
- preregister a coverage matrix, query budget, counterevidence and stop rule;
- record every visible result, upstream cluster, inclusion decision and residual risk;
- split closure into process reproducibility, cell coverage, independent entailment, decision sufficiency and residual risk;
- restrict practitioner evidence to failure probes, user burden and reopen triggers;
- say “bounded decision sufficiency,” never “the domain is complete.”

Do not yet claim:

- the full governance process is cost-effective;
- sentinel retrieval or novelty probes are necessary for every low-impact task;
- R7 achieved domain or decision closure.

### RS-02 — long-running AI work

Conditionally adopt:

- judge metamorphic tests: blind identity, order swap, fixed judge revision and deterministic or human references;
- position, compaction, restart and stale-request probes for context preservation;
- atomic claim lineage, quarantine, rollback and deterministic infection oracles instead of role-name isolation;
- termination, checkpoint namespace, interrupt/resume, crash/replay, idempotent side effects and upgrade replay tests for any graph or loop runtime;
- a narrow sampling/vote exception only where an objective oracle exists.

Keep long-term memory non-authoritative until contamination, staleness and supersession have executable tests.

### RS-03 — data and external paper boundaries

Conditionally freeze:

- provider-neutral contracts and provider-specific conditional capability gates;
- distinct `event`, `effective`, `ex`, `published`, `available`, `retrieved` and `decision` times;
- an explicit license state machine: `unknown → allowed/restricted/expired/revoked`;
- append-only revisions with parent snapshot and observed-at time;
- automatic V1 corporate actions only for frozen, golden-tested splits and cash dividends;
- an external paper observer manifest whose state never overwrites the local authoritative ledger.

Remain blocked:

- private-provider acceptance, real entitlements, retention rights and network behavior;
- external paper fills and reconciliation;
- any statement that provider `date` alone proves point-in-time availability.

### RS-04 — reuse of existing systems

Reject whole-system replacement of the authoritative path.

Conditionally adopt:

- `ExternalResearchAdapter` for frozen, read-only snapshots;
- `ExternalComponentManifest` binding repository, revision, license, dependencies, live surface, command, output hash and invalidation rules;
- `DifferentialOracle` whose disagreement creates review work and never chooses a winner automatically;
- one-way `LedgerProjection` to reporting/accounting tools;
- requested/actual source-chain recording and prefix-causality behavioral tests.

Reject live connectors, autonomous mandates, external mutable ledgers and any LLM portfolio-manager authority.

### RS-05 — assurance and independence claims

Use only these bounded terms:

- Git: `content_snapshot_anchor`;
- GitHub: `github_issued_workflow_provenance`, with state `designed_not_observed` until a real verified receipt exists;
- Codex: `platform_observable_separate_thread_review`;
- decision: `human_final_decision_by_Javen`.

Do not claim:

- Git proves author identity or independent review;
- GitHub Actions is an independent executor;
- attestation proves predicate truth, test-oracle quality or semantic correctness;
- a Codex locator is a signature, security boundary or cryptographic reviewer identity;
- multiple agents controlled by the same owner constitute organizational independence.

## Ordinary-search comparison

The independent reviewer found the governed report materially stronger on:

- source-set visibility;
- upstream de-duplication;
- counterevidence;
- uncertainty boundaries;
- reproducibility;
- explicit decision deltas.

The ordinary baseline was materially lighter and added useful software-delivery practices that RS-01 did not cover.

The comparison cannot prove the governed process superior because the two runs did not answer the same fixed question. It also contains no complete cost accounting. Therefore:

- adopt the minimal evidence-governance core experimentally for high-impact research and architecture decisions;
- do not make the full R7 process the proven default;
- repeat a genuinely same-task comparison before claiming factual or economic superiority.

## Why R8 is required

R8 is a closure round, not an attempt to erase R7’s failed status. It preregisters:

- one query per search call and explicit query-to-result attribution;
- two discovery queries and three reserved stability queries per topic;
- exact local source-byte snapshots and hashes;
- separate author claims and independent entailment review;
- a genuine same-task comparison requirement;
- automatic `bounded_incomplete` when the last stability query introduces a high-impact delta or any closure predicate remains false.

R8 was preregistered in commit `7824a63afe923d5e38c0c6f06577a7d1adfb81d5` before any R8 counted search. Its file SHA-256 is `613f2feb98707e6bcba5835632e2eba657ab98f81825a7678213de7ceddf92a8`.

## Release consequence

R7 authorizes no final completion claim. Reversible local implementation may continue where the above boundaries are explicit, but research closure, governance freeze, provider acceptance, machine provenance and product release remain separate gates.
