# 数据来源与发布边界｜原型阶段

## 当前原型来源

原型案例使用 FRED 导出的两个日收盘序列：

- NASDAQCOM：作为演示用研究对象。
- SP500：作为并列价格基准。

来源页面：

- https://fred.stlouisfed.org/series/NASDAQCOM
- https://fred.stlouisfed.org/series/SP500
- https://fredhelp.stlouisfed.org/fred/graphs/share-my-fred-graph/export-options/

## 适用边界

- 这是数据管线和审计流程的演示来源，不是最终生产数据方案。
- 当前序列是价格指数，不包含分红，因此不能直接称为总回报。
- 数据下载时保存原始 CSV，并记录来源 URL 和文件哈希。
- 所有决策计算只读取本地保存的来源文件，避免运行时来源变化造成不可复现。
- FRED 页面和序列的版权、使用和再发布限制必须在公开发布或上传 GitHub 前重新检查。

## 版本控制边界

原始数据和运行产物默认保存在本地但被 Git 忽略。版本库保存下载地址、处理代码、来源说明和可复核命令，不默认重新发布受限制的原始数据。

## 进入正式系统前仍需决定

- 目标市场和可交易资产。
- 是否需要复权价格、分红、拆分和公司行动数据。
- 数据供应商的许可、稳定性、历史覆盖、修订机制和成本。
- 基准采用价格回报、总回报还是可交易代理。
- 如何保存数据快照、版本、校验和缺失值处理结果。

## 候选调研结论

- yfinance 只作为个人研究便利层或交叉检查，不作为正式唯一事实源；其维护者说明它不是 Yahoo! 背书工具，实际数据使用受 Yahoo! 条款约束。
- Tiingo 进入正式日线候选，因为其文档区分原始/复权价格并提供分红、拆分字段；覆盖、许可、修订和成本仍需本地验收。
- Alpaca 进入未来外部纸面执行候选；纸面成交模型和市场数据计划边界必须与本地账本并列记录。
- 在供应商无关的数据快照契约通过前，不接入任何外部数据或券商 API 到核心路径。
