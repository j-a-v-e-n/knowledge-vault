# 投研纪律系统｜项目级 AI 工作规则

## 每次开始

先读取：

1. `PROJECT_CHARTER.md`
2. `RECOVERY_POINTER.md`（若存在）
3. `STATUS.md`
4. `TASK_BOARD.md`
5. `DECISIONS.md`
6. `EVIDENCE_GOVERNED_AI_SYSTEM.md`
7. 与当前任务直接相关的设计、研究和证据文件

`RECOVERY_POINTER.md` 只用于定位尚未集成的当前工作状态。它不能作为
候选通过、恢复成功、设计冻结或项目完成的证据；必须按其中记录的身份、
哈希和原始证据重新核对。若它与生成的状态视图不同，先区分“最后已集成
权威状态”和“尚未集成移动树”，不得用任一方静默覆盖另一方。

先用简短状态说明确认：已有事实、当前可用产物、未满足的保障主张、本轮目标和完成证据。

## 工作原则

- 不以 Prompt、Context、Harness、Loop、Graph 或其他流行术语直接决定架构；先还原它解决的底层问题。
- 先从最终目标倒推要求和证明义务，再生成任务。
- 研究先建立问题与覆盖地图，再形成结论；先建立主张—证据关系，再写综合报告。
- 外部资料是候选证据和反例来源，不是自动生效的项目事实。
- 实现必须链接到要求和失效模式，并验证正常、拒绝和恢复路径。
- 生成者不能单独决定高影响工作完成；使用独立上下文进行挑战或审查。
- 完成必须满足 `EVIDENCE_GOVERNED_AI_SYSTEM.md` 中适用的完成门。
- 目标明确后自主持续推进；只有触发 `LOOP_SPEC.md` 中的暂停条件才等待用户。
- 可以默认调用彼此隔离的 Codex 子代理承担研究、挑战、审查和可并行构造；高影响判断不得把共享同一未经核验摘要的代理当作独立。

## 隐私与外部访问

- 只读取本项目和完成当前任务必需的公开资料、项目文件与工具状态。
- 不读取 Gmail、私密账号、课程资料、个人通信或本项目无关文件。
- Javen 的姓名和邮箱虽可在确有必要时使用，但当前没有必要，不主动收集或传播。
- 如果未来某项工作确实需要新的个人信息，先说明具体字段、用途、保存位置和替代方案；未获明确许可前保持缺失。
- API 密钥、登录令牌、券商凭据和真实账户数据按敏感信息处理，不写入项目文件、日志或提交历史。

## 投研安全边界

- 保持个人使用、纸面优先和人工最终决策。
- 不接入真实资金，不自动执行真实交易。
- AI 不得修改或绕过确定性风险规则。
- 保护决策时点数据边界；禁止把事后信息放入事前证据。
- 不用漂亮回测、一次盈利或模型自信代替留出检验、基准和失败证据。

## 每次结束

- 运行与风险相称的验证。
- 更新实际发生变化的状态、任务、决定、研究和证据文件。
- 若工作发生在尚未集成的移动树，更新 `RECOVERY_POINTER.md`，使压缩或
  重启后的工作能够定位精确断点，同时明确尚未持久化的代码风险。
- 明确已完成、未完成、失败和未知。
- 不因 token、时间、篇幅或“看起来足够”降低完成标准。
