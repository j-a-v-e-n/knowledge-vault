# 可执行系统设计｜个人版 MVP

## 一句话定义

这是一个本地优先、纸面优先、人工最终决定、确定性规则把关、追加式账本留痕的个人投研纪律系统。AI 负责研究和建议，不拥有交易执行权。

## 当前范围

- 使用者：Javen 本人。
- 节奏：日线数据支持周、月尺度的研究和决定。
- 市场边界：暂以美国上市股票和 ETF 的研究对象为设计假设；正式数据源仍未定案。
- 数据入口：当前使用保存并哈希的 FRED CSV 验证管线；它不是最终数据供应商，也不是正式总回报基准。
- 执行入口：当前只有本地 PaperAccount；不连接券商、不发送真实订单、不使用真实资金。
- 记录入口：项目 Markdown 保存长期状态；运行账本使用追加式 JSONL 哈希链。
- 版本与恢复：代码、设计、决定、配置和验收摘要由 Git 记录，并推送到现有 GitHub 远端形成异地副本；密钥、私人数据和不可公开授权的数据不得进入版本历史。

## 核心运行链

```text
研究问题
  → 来源快照与证据包
  → AI 分析建议
  → 人工接受/拒绝/延后/修改
  → 确定性风险闸门
  → 本地纸面执行适配器
  → 成交/拦截/失败事件
  → 与预先指定基准并列复盘
  → 记录反馈并进入下一轮
```

任何分支失败都必须产生日志；“没有交易”“不知道”“无法验证”是合法结果。

## 组件与职责

| 组件 | 当前实现 | 权限边界 |
| --- | --- | --- |
| DataSnapshot / DataSource | `prototype/contracts.py`；FRED 运行器先用本地文件 | 必须区分观察时间、可见时间、获取时间、来源版本和原始内容哈希 |
| EvidencePacket | `prototype/discipline_system.py` | 事实、推断、假设、未知和失效条件分开；不把 AI 摘要当事实 |
| Recommendation | `prototype/discipline_system.py` | 可以买入、卖出、等待或不交易；不得直接提交订单 |
| Decision | `prototype/discipline_system.py` | 人记录最终选择、理由、偏离和情绪状态 |
| RiskGate | `evaluate_paper_order` 与 `record_paper_workflow` | 规则版本固定；AI 和订单请求不能绕过；买入额度按实际数量、价格和账户现金计算 |
| ExecutionAdapter | `LocalPaperExecutionAdapter` | 只返回结构化成交、拒绝或未知结果；当前不存在真实执行适配器 |
| PaperAccount | `prototype/paper.py` | 本地现金、持仓、成交和市值；重复订单号拒绝 |
| Backtest | `prototype/backtest.py` | 成本、开发/留出区间、基准和无未来信息审计 |
| ResearchRun | `prototype/research_run.py` | 把历史检验、纸面工作流和复盘写进同一研究运行账本 |
| Ledger | `AppendOnlyLedger` | 追加写入、链校验和篡改发现；不是绝对不可篡改存储 |
| Review | `PaperReview` 与运行器 | 结果与预先指定基准并列；不只展示盈利结果 |

## 必须保持的不变量

- 决策输入不能包含决策时点之后才可见的数据。
- 进入/退出等事后结果数据不能回写决策快照。
- 订单实际名义金额不能只由调用方自报比例决定。
- 风险闸门拒绝时，账户现金、持仓和成交不得改变。
- 账户执行失败不能伪装成风险拒绝或成功成交。
- 相同订单号重试不能重复改变账户状态。
- 数据或计算版本改变时，旧运行结果不能被静默覆盖。
- 人工偏离可以发生，但必须显式记录，且仍受同一风险闸门约束。
- 账本中的建议、决定、闸门、成交、失败和复盘必须能关联到版本与来源快照。

## 当前可复核命令

在项目目录执行：

    python3 -m unittest discover -s prototype/tests -v
    python3 -m prototype.run_real_data_case
    python3 -m prototype.run_real_data_backtest
    python3 -m prototype.run_paper_suite
    python3 -m prototype.run_unified_prototype_case
    python3 -m prototype.run_real_data_unified
    python3 -m prototype.run_contract_faults

运行结果位于 `prototype/data/runs/`，原始数据和运行产物默认被 Git 忽略；版本发布前必须单独检查数据许可。

## 当前完成定义

当前 MVP 只有在以下证据都存在时，才可称为“纸面闭环可用”：

- 项目资料能恢复目标、状态、任务、决定和下一步。
- 真实来源文件能被保存、哈希、重跑和检测修订。
- 历史检验明确成本、开发/留出、基准和无未来信息审计。
- 连续纸面案例覆盖通过、拒绝、人工偏离、执行失败和复盘。
- 真实来源统一运行能把历史检验、纸面执行、账本和复盘串联。
- 故障注入覆盖未来数据、异常成交状态、未知状态和重复提交。
- 所有验证命令通过，账本可以重新校验。
- 发布状态有明确提交并已推送到远端；从独立临时目录恢复后，能够重建环境并重复核心验收。

这些条件证明的是流程和纪律机制可核对，不证明任何投资策略有优势。

## 仍未实现

- 新闻和基本面来源的可见时间快照。
- 正式复权价格、分红、拆分、公司行动和总回报基准。
- 退市证券与生存者偏差处理。
- Tiingo 等正式日线数据候选的适配器验收。
- Alpaca 或 IBKR 外部纸面适配器的部分成交、认证、断线和对账实验。
- 多资产组合、再平衡、提醒、界面和部署。
- 被 Git 忽略的关键运行证据如何归档、校验和恢复，以及完整恢复演练。
- 真实资金和真实交易路径。

## 外部适配器进入门槛

未来若接入数据供应商或纸面券商，必须先通过：

- 明确个人使用许可和缓存/再发布边界。
- 保存原始响应、请求参数、获取时间、版本和哈希。
- 对账本地订单、供应商订单、成交回报、账户余额和持仓。
- 注入断线、重复提交、认证失效、部分成交、未知状态和服务方修订。
- 证明纸面端点和真实端点在代码和权限上隔离。
- 适配器失败时默认停止并留痕，不能自动升级为真实交易。

## 未来扩展

通用项目工作系统、多人服务、权限、对外发布和商业化只进入路线图。Git/GitHub 版本历史与恢复能力是当前系统的基础设施，不再作为远期功能。未来扩展不改变当前个人版 MVP 的核心边界，除非重新确认目标和验收标准。
