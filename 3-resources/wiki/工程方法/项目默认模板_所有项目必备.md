# 项目默认模板 — 所有 project 必备 component

> Javen 2026-05-16 explicit 指令："连我这个小白都知道什么项目都有这些部分，我让你学管理学是真的要用的，而不是只给我编译完我理解然后你还是老样子"。
>
> 本页是 default checklist。任何 task / project / wiki design 时 AI **强制 reference**，缺一就是 violation cargo cult of expertise。

---

## 0. 强制 enforcement 机制

**触发条件**：设计任何 project / candidate project / task / multi-step workflow / pipeline。

**Action**：本页所有 5 个 phase 的 component **必须出现** in design doc。缺一个就在 design doc 顶部标 `⚠️ Missing: [component]`，不允许悄悄省略。

**例外**：极简一次性 task (单 file edit / 单 grep) 可省略；任何"会 ship 给 user 或自动 run 多次" 的 work item 都必须走全套。

## 1. Engineering Discipline ABC（5 phase）

### Phase A: Design / Spec

**Default include**（缺一就是 violation）：

1. **Problem statement** — what / why / for whom（Marty Cagan: spec start with user problem 不是 solution）
2. **Acceptance criteria** — Definition of Done 明文写出，可 verify
3. **Alternatives considered** — 至少列 2-3 个其他方案 + 为啥不选（防 anchor bias / single-path）
4. **Risk register** — 4 risks (Marty Cagan): value / usability / feasibility / business viability
5. **Decision record** — 关键 choice + rationale + date + author
6. **Adversarial review** — spawn 第 2 个 reviewer agent (fresh perspective, brutally honest) audit design 找漏（CLAUDE.md "重大决定不允许 single-agent" L2+ default）

### Phase B: Implementation

**Default include**：

1. **Test** — unit test (function-level) + integration test (跨 module) + e2e test (user flow)。No code merge without test。Coverage target ≥ 70%
2. **Code review** — peer review or AI reviewer (单 commit 不绕过)
3. **Lint / format** — automated style check (Black / Prettier / etc.)
4. **Doc** — README + inline docstring + API spec
5. **Logging** — structured log at decision points (not just printf)
6. **Error handling** — try-except + graceful degrade，不 panic crash
7. **Config externalization** — env var / config file，不 hardcode

### Phase C: Deploy / Launch

**Default include**：

1. **Staged rollout** — local dev → staging → canary → prod（不直接 prod ship）
2. **Rollback plan** — 写明"如果出问题怎么回退"。Git tag + DB migration reversible
3. **Pre-launch checklist** — manual verify (smoke test) before announcing
4. **Cost guard** — set spending cap / quota (any API / compute resource 启动前必须有 ceiling — lesson from ECE284 LOSO incident)

### Phase D: Run / Monitor

**Default include**：

1. **Monitoring** — uptime / latency / error rate / cost dashboard
2. **Alerting** — threshold breach 触发通知 (Slack / email / Pushover)
3. **Heartbeat** — 长 job 每 N 分钟写 progress log (lesson from background daemon)
4. **SLI / SLO** (Google SRE) — Service Level Indicator 量化 (response time p95 etc.) + Service Level Objective 目标 (99.9% uptime)
5. **Dashboard** — Javen 一眼看到 health (cost / usage / errors)

### Phase E: Maintain / Improve

**Default include**：

1. **Scheduled audit** — weekly / monthly review (KPI / cost / user feedback)
2. **Post-mortem** — bug 触发 → blameless analysis 5 Whys → lesson 进 `lessons.md`
3. **Pivot-or-persevere review** — periodic 触发 (60-day for solo project / quarterly for team work) decide kill / continue / scale
4. **Documentation drift catch** — 代码改了 doc 没改 = warning

## 2. Management / PM ABC

**Default include**（任何 multi-step task）：

1. **Discovery** — 用户 / stakeholder 访谈 (Marty Cagan 5+ interview rule) before build
2. **Competitive analysis** — 至少看 3 个 existing 方案 (避免 reinvent wheel)
3. **OKR / KPI** — measurable target，不是 "做好它" 这种 fuzzy goal
4. **Milestone breakdown** — 任务切到 ≤ 1-2 weeks chunk
5. **Kanban WIP limit** — 同时 in-progress 任务 ≤ 3 (防 context switching)
6. **Weekly retro** — what worked / what didn't / what to change
7. **Stakeholder communication** — async update (vault / Slack / dashboard)，不依赖 sync meeting

## 3. AI Workflow Specific ABC

**Default include**（任何 AI agent / Claude Code workflow）：

1. **Multi-agent for L2+ decisions** — adversarial reviewer 强制 (CLAUDE.md 已有 rule)
2. **Source of truth in vault** — fact commit 不依赖 session memory (lesson ⑮ identity / lesson ⑭ verbatim)
3. **PDCA mandatory Check step** — deliverable edit 完必须 audit (CLAUDE.md 已有 rule)
4. **SessionStart hook** — auto-inject lessons.md + profile-facts.md (现在 deploy)
5. **Stop hook reviewer** — Cargo Cult Detector audit each reply (现在 deploy)
6. **Daily transcript audit** — cron 跑 reviewer 检查近 24h pattern drift
7. **AI 分工** — engineer / designer / marketer / researcher / reviewer / DevOps agent (T-shape org)，user 只 do product judgment + customer interview + final approve

## 4. 反 pattern (我之前犯过的)

- ❌ Wiki 写 5000 字 design 但**没 spawn reviewer**（缺 Phase A.6）
- ❌ 3 个 candidate project design 但**没 test / monitoring / rollback** spec（缺 Phase B/C/D）
- ❌ Project plan 但**没 risk register**（缺 Phase A.4）
- ❌ Spec 只列 1 个 solution 不列 alternatives（缺 Phase A.3 → anchor bias）
- ❌ "已落盘 ✓" reassurance 后不 verify content correct（缺 PDCA Check）
- ❌ Long-running job 没 heartbeat / cost guard（缺 Phase D.3 / Phase C.4 — lesson from ECE284 LOSO incident）
