# 本地大模型推理 (Local LLM Inference)

> 把大语言模型跑在自己机器（笔记本 / 工作站）上，不依赖 cloud API。2026 年这条路径正在从"DIY 极客玩具"变成"实用工具栈"，关键 enabler 是 (a) 开源前沿模型（DeepSeek / Llama / Qwen）+ (b) Apple Silicon 大内存 Mac + (c) 量化 + MoE 等工程取舍。

---

## 核心论点

**2024 之前**：本地推理是"小模型 toy"——能跑 7B Llama 但不能跑 GPT-4 级别
**2026 现在**：本地推理能跑**前沿模型**（DeepSeek V4 MoE，1.6T 参数，量化后塞进 128GB Mac）

→ **大模型的"必须用 API" 神话被打破**——见 [[2026-05-11_Antirez_4000行C本地推理|Antirez ds4 项目]]

---

## 关键技术 enabler

### 1. 量化 (Quantization)

把模型权重从 16-bit 浮点压到 8 / 4 / 2 bit 整数。例：
- FP16：每参数 2 bytes
- INT8：每参数 1 byte（半压）
- INT4：每参数 0.5 byte（4 倍压）
- IQ2_XXS：每参数 ~0.25 byte（8 倍压）

**取舍**：压缩越狠，质量损失越大，但能塞进更小内存

**经验值**：
- 7B 全 FP16：14GB
- 7B INT4：4GB（**M3 Pro 16GB 能跑**）
- 70B INT4：35GB（M3 Max 64GB+ 能跑）
- 1.6T MoE 2-bit (only routed experts)：~64-128GB（M3 Max 128GB 能跑）

### 2. MoE (Mixture of Experts) 架构利用

DeepSeek V4 是 MoE：1.6T 总参数，但**单次推理只激活 49B**

**为什么 MoE 适合本地推理**：
- 大部分 expert weights 不在被激活的 path 上
- 可以把不活跃 weights 放 SSD，活跃 weights 放 RAM
- 用 `mmap()` 让 OS 自动管理 swap

→ Antirez ds4 的核心 trick

### 3. Apple Silicon 优化 (Unified Memory)

Apple Silicon Macs（M1/M2/M3/M4）的关键特性：
- **Unified Memory** —— CPU 和 GPU 共享同一块 RAM，不需要 host-device transfer
- M3 Max 可以买到 128GB unified memory
- M3 Ultra 可以买到 512GB unified memory

**vs Nvidia GPU**：
- H100 GPU 80GB VRAM 但 RAM 跟 GPU 分离，big context 反复 copy 慢
- M3 Ultra 512GB unified 直接给 GPU 用，无 copy 开销

**结果**：消费级 Mac 在大 context 推理上反而比 enterprise GPU 有 niche 优势

### 4. Metal Shading Language

Apple GPU 原生 shader 语言。绕过 CUDA / Vulkan 直接编程 Apple GPU
- 比走 PyTorch + MLX 等 framework 快
- 但开发难度高（要懂 GPU kernel 编程）
- Antirez ds4 直接写 Metal，跑得最快

## 工具栈对比 (2026 实测)

| 工具 | 难度 | 适合 model | M3 Max 性能 | 适合场景 |
|---|---|---|---|---|
| **Ollama** | ★★★★★ (一行命令) | 7B-70B dense | 30-100 t/s | 个人新手、快速试 |
| **LM Studio** | ★★★★★ (GUI) | 7B-70B dense | 50-100 t/s | 不写代码的非技术用户 |
| **MLX** | ★★★ (Python) | 7B-70B+ | 230 t/s (7B) | Apple Silicon 优化、高性能 |
| **llama.cpp** | ★★ (CLI + 配置) | 7B-100B+ | 20-100 t/s | 生产稳定、跨平台 |
| **Antirez ds4** | ★ (build from source) | DeepSeek V4 MoE 1.6T | 26.68 t/s | 极致性能 + 大模型 |
| **vLLM** | ★ (server-side) | 7B-100B | 取决于 GPU | Linux GPU server，高吞吐 |

## "护城河"经济学分析

视频引用：
> "大模型最值钱的护城河正在从'谁有算力'转向'谁有权重'，这两样东西 DeepSeek 都白送了。"

**算账**：

**Cloud API 路线**：
- Claude Opus 4.7: $15 input + $75 output per M tokens
- 重度用户月用 5M tokens = $75-$375/月
- 年 $900-$4500

**本地推理路线**：
- 一次性买 M3 Max 64GB Mac: $3500
- 跑 Llama-3 70B INT4 + 自己电费 ~$5/月
- 5 年 TCO ~$3800
- vs cloud 5 年 $4500-$22500

**break-even**：6-12 个月

**但这账只对**：
- 不需要 frontier model（Claude Opus 仍最强）
- 不需要 SLA（生产 enterprise 不能依赖你的 MacBook）
- 不需要 multi-modal（语音 / 视觉 / video）

→ 本地推理 fit "个人开发者 + privacy 敏感 + 高频小任务"，不 fit "企业 SaaS production"

## Javen 实战建议

### 你 Mac 配置先 audit

不知道你 Mac 具体配置——但典型 ECE 学生：
- M2/M3 **Pro 16GB**：能跑 7B INT4
- M2/M3 **Pro 32GB**：能跑 13B INT4 + 量化版 27B
- M3 **Max 64GB**：能跑 70B INT4

**如果你是 16GB 配置** → 跑 DeepSeek-Coder 6.7B（专门优化代码）+ Llama-3 8B（通用），完全够日常

### 推荐 setup (15 分钟搞定)

```bash
# 1. 装 Ollama
brew install ollama

# 2. 启动服务
ollama serve

# 3. 拉 model
ollama pull deepseek-coder:6.7b
ollama pull llama3:8b
ollama pull qwen2.5-coder:7b

# 4. 跑
ollama run deepseek-coder:6.7b
```

### 用本地模型的 use case（不要替换 Claude，是补充）

**适合本地**：
- 命名 / docstring / comment 生成（不敏感、批量、低 stake）
- 离线场景（飞机 / 火车 / 偏远）
- vault inbox 字幕批量整理（你 douyin-favorites 那些）
- 低预算项目（你给朋友帮忙看代码）

**不适合本地**：
- 关键代码（项目报告 submit 前的最后审查）
- 复杂多步推理（用 Claude Opus / Sonnet）
- 你 vault 主对话（Claude Code 体验远好于任何本地）

## ⚠️ 矛盾与未解决问题

- **量化质量损失的量化**（meta）：2-bit vs FP16 在医疗 / 法律 / 安全 critical task 上质量损失多少？缺系统 benchmark
- **Apple Silicon vs NVIDIA H100/B100 长期 trajectory**：Apple 大内存 + unified memory 优势能持续多久？M4 Ultra 后会不会进一步缩小 gap？
- **本地推理的"模型选择疲劳"**：每周新 model 出，普通用户怎么知道用哪个？需要"local LLM benchmark dashboard"
