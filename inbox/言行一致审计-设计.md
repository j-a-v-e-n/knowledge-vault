# 言行一致审计（walk-the-talk conformance）— 设计稿

## 0. 要解决什么

冻结文件（CHARTER/NORTH-STAR/criteria + sha 钉）防的是**篡改**：墙上贴的法律没被偷改。
但没有任何机制证明每个环**运行时真的照章程办事**——"墙上一套、代码另一套"是 owner 最忌惮的失效。
本审计给每个环产出一个可核对的 **言行一致状态：verified / 未校验 / 违背**，显示在工作台架构树上。

## 1. 三段管线（owner 设计，逐字采纳）

**Stage 1 — 自检（对照圣经查遗漏）**：环跑完后，同一会话内重读自己的章程/要求清单，
逐条对照本次 run，报告**漏了什么**。目的：便宜地捞回忠诚但会犯错的模型的诚实疏忽。最先跑、在环内跑。

**Stage 2 — 代码核（零误差裁判）**：机器可验证的断言，对着 run 日志/工件跑代码：
要求的检查真的开过火吗？冻结范围真的零写入吗？凡是"事实形"的断言全部走这段。

**Stage 3 — 独立交叉核（只管判断形断言）**：不同 checkpoint 的模型 / 独立审计视角 / 市场信号，
只用于代码判不了的"意见形"断言。

## 2. 证据规则（铁律，管线的宪法）

| 主张类型 | 有权下结论的 Stage | 说明 |
|---|---|---|
| "这个环这次 run 漏了某要求" | Stage 1 可**报告并补救** | 自报只用于纠错回收 |
| "这个环忠于章程"（言行一致=verified） | **只有 Stage 2 + Stage 3** | 见下条铁律 |
| 事实形断言（某检查开火过 / 某路径零写入 / 某 sha 匹配） | **Stage 2 独裁** | 代码是零误差裁判 |
| 判断形断言（kill 理由质量 / 语域是否合规 / 提案是否越权） | Stage 3（多源独立） | 独立性是硬门槛 |

**铁律（owner 逐字精神）**：Stage 1 自报**永远不算**"环是忠诚的"之证据——
真在跑偏的环不能被信任会自报跑偏（造成跑偏的盲点同样使自检失明）。
忠诚/一致的裁决只来自 Stage 2（代码）与 Stage 3（独立来源），绝不来自 Stage 1。

## 3. 独立性方法论（缩小"AI 评 AI"的表面积）

1. **先问"能不能代码判"**。每条一致性断言先过这个问题：能对着日志/工件用代码验证吗？
   能 → 归 Stage 2，一票定案，不许再引入模型意见。
2. 只有真需要判断的断言才进 Stage 3，且**独立性必须来自不同来源，绝不来自重复**：
   - 不同 checkpoint 的模型（不是干活的那个）；或
   - 交叉视角：执行者 vs 独立审计者 vs 市场信号。
3. **明确拒绝"同一模型自查 N 遍"**：相关错误不叠乘，只是同一个盲点盖 N 次章——
   产出假信心，恰是"墙上一套代码一套"的变装版。只有来源独立之后，
   重复到共识才合法地把错误概率指数下压。

## 5. 运行与呈现

- **节奏**：每周一跑（搭监事会列车尾，先于周报出）；单环 run 后的 Stage 1 自检随环内进行。
- **呈现**：架构树每环一枚徽章 verified / 未校验 / 违背 + 点开看逐断言证据（同说明书的溯源格式：断言 → 证据文件 → 判定代码路径）。
- **违背处理**：任何 Stage 2 断言失败 → 徽章立即"违背" + 0-工作台 出告警卡（照 ops 告警卡样式），绝不静默降级。
- **审计器自身的完整性**：断言清单与判定代码入库、sha 钉入每份审计报告（与 CHARTER 同一套钉法）；改断言 = 过 owner 卡。

## 6. 造价与边界（诚实）

- Stage 2 全部是读日志/git 的小脚本，估 1-2 个会话建完；零新依赖。
- Stage 3 需要第二个模型 checkpoint 的调用额度（判断形断言每周抽样量很小）；用哪个 checkpoint、抽样多大，建时再报你批。
- 在你批准并建成之前，工作台上所有环的言行一致徽章一律如实显示「未校验」——绝不自我认证。
