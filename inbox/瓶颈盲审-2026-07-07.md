## 2. Top 3 瓶颈（按"今天对终极目标的扼制力"排序）

### 瓶颈 1：市场层从未开火——乘法公式的零点（混合型：数据 + 工程 + 人力）

整个公式是乘法，任何一项为零全盘为零，而当前为零的正是最靠近钱的一层。三重成因，各自定性：

- **数据缺口**：commercial 候选池冷启动为空——池子只吃两种料：exceeds-envelope 击杀（至今 `envelope_kills=0`，`kpi.json` Ring2）和周冠军（至今无冠军）。多跑几天自然会有料，这部分等得起。
- **工程缺口**：gate 两天只放行 2/16，且第二天被格式回归**整日清零**——上游供弹能力本身不稳（详见瓶颈 2）。
- **人力缺口（owner-gated，by design）**：即使有探针，发布必须 owner 亲手发帖 + 填回执；收真钱必须 owner 付 Vercel Pro。**这是全链路上仅有的两个无法自动化的动作，且都卡在关键路径上。**（盲审期间三条改进提案已获裁决——1批/1缓/1批限测量，作战板 03:30 版——该项人力阻塞已解除，剩下的 owner 动作就是发帖与付费两件。）

### 瓶颈 2：idea→可交付产品的转化链断了两处（工程缺口）

实测转化率 0/2，断点都已定位【查到的】：

1. **生成端格式回归**：7-07 全部 8 个 idea 死于同一 C3 格式错。修复（`repair_prior_art()`）已作为 exp-001 实验上线（离线回放 10/10 + 活体种植验证，作战板 03:30 版；owner 已裁决"批"）——但改动**仍未 commit 入库**（git working tree +53/-10），且**无一次真实 daily run 的实战数据**，时间盒至 07-13（见附录 A 时间线）。
2. **gate escape**：agentspc 带着一个 v2 判不动的 ruler 过了 gate，v2 只能 declare 弃建。supervisor 提案 P2 针对此（自标"证据薄，单样本"）。

另计【查到的】：v2 的 18/50 cycle 死在 design 阶段，每个白烧 $0.76–0.95【我推断的：合计约 $14–17 打了水漂】。这是转化链的慢性失血，但优先级低于上面两个断点——它浪费的是"尚未接通市场的那一层"的效率。

### 瓶颈 3：产能跑步机——机器的绝大部分马力花在不复利的内部循环上（工程/设计缺口）

【查到的】：
- v2 51 个 cycle 里 **~44 个在反复重解同 6 个玩具**（csv2md ×8、semvercmp ×8、slugify ×7、wordfreq ×7、dotenv2json ×7、jsonmerge ×7），每次从零重解（同一任务产物 md5 各不相同）、**无沉淀无复利**；只有 3 个 cycle 跑过真实产品。
- student 支柱在反复重读同 ~6 篇论文（bitter-lesson-diffusion ×14、prompt-coverage-adequacy ×11…）。
- self-improve 采纳数 = 0（全周期 `m4.sealed_adoptions=0`）。
- **一个假指标**：m3"代码验证率"恒等于 0.5714——因为 `CLAIMS.jsonl` 是固定 7 行模板（永远 4 verified + 3 declared），`trend.json` 拿它报 "non_degrading" 属于**量了一把焊死的尺子**。这是本次盲审发现的唯一一处违反"验证器先校准"原则的实锤。

打个比方：这台机器像一个训练极其刻苦、动作极其标准的射击队——但训练弹道全打在自家靶场的 6 个固定靶上，真正的赛场（市场）一枪未发，而记分牌上有一格（m3）是印刷体。
